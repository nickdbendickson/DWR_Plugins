DamSafety Setup 1.0.9 - fill missing dam height and storage from the NID
=========================================================================

Why
  1.0.8 keeps Next off while a dam's height or storage is 0, so the Runner never gets
  0 ft / 0 ac-ft. Many DWR records have no height or storage (42 of the 74 Cass County
  dams). This version fills what it can from the National Inventory of Dams (NID); typing
  the numbers in stays the fallback.

What changed (dam page)
  * The NID layer in the suite data folder (the offline pack's hydro/NID_dams.gpkg, found
    by the folder scan) fills blanks as soon as the dams are listed. Read-only; no network.
  * "Fill from NID (online)" asks the NID web service (nid.sec.usace.army.mil) for the
    current dam. Only on that click: the wizard makes no network call by itself. It goes
    through QGIS's network settings (proxy), does not freeze the window, gives up after
    15 s and says so; the values can then be typed in.
  * A dam is matched by its NID id (DWR national_id), else by the nearest NID dam within
    100 m of the DWR point.
  * Only blanks are filled. 0 counts as blank (DWR stores "not recorded" as 0). A DWR value
    above 0 is never replaced, and a storage still blank takes the DWR normal pool volume
    before the NID. A value typed in is kept by the online fill.
  * NID height: NID_HEIGHT, else DAM_HEIGHT (ft). NID storage: MAX_STORAGE, else
    NID_STORAGE, else NORMAL_STORAGE (ac-ft).
  * A grey note beside each value says where it came from: "from DWR", "from DWR (normal
    pool volume)", "from NID ND00189", "typed in". The tooltip names the NID field and how
    the dam was matched. The DEM and Run pages show the same.
  * Max storage goes up to 50,000,000 ac-ft (the NID gives 26,000,000 for Snake Creek /
    Lake Sakakawea; the old 5,000,000 cap would have cut it silently).

Hand-off to the Runner
  * The wizard answers carry height_source and storage_source; the Runner parameters carry
    HEIGHT_SOURCE and STORAGE_SOURCE, and the QGIS log ("DamSafety Setup") records them.
    The Runner's processing dialog only reads parameters it defines, so these extra keys
    do not change the run and are not yet written to the Runner's run_report.json.

Dam reader fix
  * A dam with no point (blank or 0, 0) now takes the midpoint of its dam line, transformed
    to EPSG:4326 like the inventory points, and is marked "point from the dam line". The old
    code looked the line up but only set from_line = False and never used it (and only when
    the lines sat in the same GeoPackage, which the pack does not do). The unused
    _line_midpoints helper, which would have replaced every inventory point, is gone.
    Three DWR dams (all Sargent County) have no point; all three have a dam line.

Tests
