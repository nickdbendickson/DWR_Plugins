Every Boann run now keeps the host's times in its statistics (stats["profile"]): on the Apple GPU, the time Python spent encoding the GPU's commands and the time it waited for the GPU; on the CPU build, the time inside the kernels. With --profile on Boann's command line (boann.py run DECK.par --profile [--stats-json PATH]), --profile on the speed test, or DAMSAFETY_MF_PROFILE=1, the full profile adds: the GPU's own time per step (the command buffer's GPUStartTime / GPUEndTime) and per kernel (the first 2 steps of each batch are sent one kernel per command buffer, the same dispatches in the same order; Apple GPUs sample counters only at pass boundaries), and how much of the wet window is water: the share of cells that are wet, the share in the 16 / 32 / 64-cell tiles that hold water or touch one that does (what a dry-tile skip on the GPU would still run), and the share in the row ranges of the CPU dry-cell skip's rule. DAMSAFETY_MF_TG=WxH sets the Metal threadgroup size for speed tests (the grids do not change; the outflow and clipped totals are summed per SIMD group before rounding, so they can move by a rounding unit).
