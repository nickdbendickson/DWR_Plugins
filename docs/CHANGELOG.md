- **Runner 3.10.60 / Screening 0.17.39 (numbered 3.10.43 / 0.17.35 on its branch): `gdal.Warp` without source overviews (`-ovr NONE`).** `gdal.Warp`'s default (`-ovr AUTO`) resampled a coarser model grid from a 1 m tile/VRT's nearest overview instead of its 1 m cells (a 5 m grid from a 4 m overview, 10 m from an 8 m one). A shared `core/warp_opts.py` (byte-identical in Runner and Screening) now passes `overviewLevel='NONE'` (QGIS 3.34's GDAL 3.8.5 keyword; `-ovr NONE` otherwise) everywhere terrain is warped — Runner `gdal_io.GdalTerrain`/`read_like`/`hecras_model`, Screening `TerrainLoader.load`, Find Ponds, the terrain cache and Download DEM's local DEM. Grids from a DEM with overviews shift slightly (≈1–2 cm mean |dz|, up to 5–12 cm for NEAREST; ~0 bias), so baselines may move; a DEM without overviews is identical. Test: `tests/test_warp_no_overviews.py`.
- **Runner 3.10.59 (numbered 3.10.56 on its branch): HEC-RAS package gets the culverts and bridges ANUGA used; terrain-CRS guard.** `core/hecras_structures.py`: culverts and bridges can be taken from another run of the dam (`structures_from` = its dam folder / `run_report.json`; Processing "Culverts and bridges from another run"), e.g. the ANUGA run when the package is built from a LISFLOOD-FP run; culverts take the inverts ANUGA used (`anuga/anuga_job.npz`) when the report leaves them empty; a bridge/notch on the same crossing as a culvert becomes an open gap in that culvert's road weir. The package stops if the terrain GeoTIFF lost its EPSG code / doesn't match `Projection.prj` / `proj.db` is unreachable. 2D-internal culvert connections are routing type 1 (type 3 stopped HEC-RAS). Connection lines are breaklines built into the computation points (`structure_breaklines`, on); each weir face / culvert invert is checked against its cells and raised + 0.01 ft if below (`structure_cell_fit`, on); the terrain is never changed.
- **Runner 3.10.58 (numbered 3.10.55 on its branch): ANUGA outer edges are outflow-only (run queue QA a_culvert_anuga).** ANUGA's outer edges were `anuga.Transmissive_boundary`, which copies the inside momentum to the edge, so water moving inward next to an edge (a pond against a clipped edge, an eddy, flow along the edge) was fed in from outside — the NDDOT culvert run ended with 8.25 M m³ in the domain for 1.99 M m³ of breach inflow (4.15×, a 10 ft edge pond); the 2026-10-15 structures run 1.51×. Now the edges are transmissive where water leaves and mirror the normal momentum where it would enter (zero mass flux), so no edge gains water (`edge_bc`: `outflow` default, `transmissive` = before). ANUGA results change wherever the flood reaches the mesh edge; a run that stayed inside is unchanged. The worker records a volume balance (in domain / (initial + breach inflow)); above 1.02 → a "volume check FAILED" warning.

- **Runner 3.10.38 (#117; numbered 3.10.35 on its branch until #120 took it): ANUGA checkpoints, partial results and resume, on for long runs.** **Default rule:** a run that simulates ≥ 12 h or is expected to have ≥ 50,000 triangles (gmsh: its count; ANUGA's mesher: 1.5 × area / largest triangle area per region) checkpoints every 30 wall-clock minutes (keep 2) and writes partial results every 10 minutes; a short run is unchanged (same job file, no extra files). `NDBREACH_ANUGA_CHECKPOINT_MIN=0` (or `off`) switches it off; a number > 0 forces it on at that cadence. ANUGA 4.0.1's `domain.set_checkpointing` (`NDBREACH_ANUGA_CHECKPOINT_MIN` wall-clock minutes or `NDBREACH_ANUGA_CHECKPOINT_STEPS` yield steps) pickles the domain, with the worker's max depth / velocity / WSE and arrival-time operator, to `anuga/anuga_checkpoints/<job fingerprint>/`; the newest `NDBREACH_ANUGA_CHECKPOINT_KEEP` (2) are kept and `checkpoint.json` lists the complete ones. `anuga/anuga_partial.npz` (the envelope grids so far, written atomically) follows every checkpoint, every `NDBREACH_ANUGA_PARTIAL_MIN` minutes and SIGTERM / Cancel (SIGTERM first when checkpoints are on). `NDBREACH_ANUGA_RESUME=1`, or the run's Resume with checkpoints on, continues the same job from its newest checkpoint that loads; another job starts over.
