about=Classifies dam hazard under the North Dakota Dam Safety Standards (REG_05.2026) and USBR ACER TM 11. Consolidates NSI / ND GIS Hub address points, POIs and FEMA_Structures building outlines inside the study area (raster extent + 25 ft) against dam-break Depth, Velocity and Arrival rasters (GPKG, CSV, XLSX outputs), joins points to building outlines with 5-ft edge-buffer hazard zones, and generates ACER-11 (USBR TM 11, 1988) hazard classification rasters for houses on foundations and mobile homes.

    2.23.11 - audit 2026-11-08 (correctness, batch 2): H19 - a multi-breach run where some scenarios have a Vmax raster and others do not is now refused (a clear error naming the scenarios) instead of classifying the data-less scenarios at velocity 0 (which reads the ACER zone off the curves at v=0 and can lower the governing class) or silently forcing the whole run to the depth-only 1D criterion. The whole-run 1D fallback fires only when every breach lacks velocity; single-breach, all-have-velocity, all-missing and user-set-1D runs are unchanged. Fail-closed: supply the Vmax raster for every breach scenario, or choose the 1D (depth-only) criterion.
    2.23.10 - audit 2026-11-07 (correctness): the sensitivity sweep now classifies each scaled structure on its peak depth / peak wet-cell velocity pair, matching the unscaled base row (2.22.3 option C), instead of the pre-2.22.3 per-cell minimum - removing spurious optimistic zone flips and the LOW-collapse for a structure with no velocity raster. Sensitivity-table flip counts and per-factor classes move in the conservative direction; the classification itself is unchanged. Shared damsuite loss.py: a flooded structure with no known arrival time is counted as no warning (not the longest/best band), so the population-at-risk warning-time split and, with a signed rate table, the loss-of-life total are no longer understated; the count is reported. New tests test_sensitivity_peak_pair.py and test_loss_unknown_arrival.py.
    2.23.9 - damsuite 1.18.9 / xlsx_lite 1.5.0 (security audit pass 3, Nick 2026-11-06): the shared .xlsx reader is bounded. A 704-byte damsuite_settings.xlsx naming a cell at row 50,000,000 made read() build a 50-million-row table and freeze QGIS; a sheet past Excel's limits (1,048,576 rows, 16,384 columns), a padded table over 2,000,000 cells or a part that unpacks to more than 64 MB now raises XlsxTooLarge (a ValueError), so the settings file is refused with a plain message (SettingsError) before anything large is allocated. Nothing else in this plugin changes.
