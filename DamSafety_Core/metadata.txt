Each DamSafety plugin's damsuite/ is a two-line shim onto this plugin, so a fix made here reaches every plugin at once and no two plugins can disagree. Every other DamSafety plugin lists this one in plugin_dependencies: QGIS offers to install it when one of them is installed.

    1.3.0 (2026-11-13; a sample dam to try the suite on: the Dam suite home has a new button, Try the sample dam. It puts one real North Dakota dam (Swan Buffalo Detention Dam 12 near Absaraka, DWR-2801: its dam record and 10 m terrain in EPSG:5070, metres) in the Dams folder and opens the breach Runner with the Dams folder, the dam and its terrain filled in. The sample comes from the offline pack when the pack has it (DamSafety Data 1.11.0 writes it as the last step of a pack build); otherwise the terrain is downloaded from the USGS 3DEP elevation service, about 29 MB, after a question, in the background, and the same button cancels it. The terrain is checked before it is kept (the sample's grid, plausible ground in metres, no holes). A dam record or terrain file already in the dam folder is never replaced, and nothing is written into an offline pack from the window. The window offers a quick first try at a 30 m cell (nine times fewer cells than the 10 m default, which is slow on this dam's flat plain) and says to set the cell back afterwards. An empty Dams folder's summary line points to the button. New module damsuite.sample_dam; suite_home.point_window_at also hands the Runner a terrain file and a cell size when the row has them. A run of the sample is not a hazard determination for that dam. damsuite/FILES.json refreshed.)
    1.1.1 (2026-11-12; NoData receptors: on a depth grid coarser than NODATA_NEIGHBOURHOOD_MIN_CELL_M = 20 m (larger cell side, converted to metres; strictly greater than 20 m) a receptor whose cell is NoData takes the peak depth and peak velocity from wet cells in the 3x3 neighbourhood or the footprint (option C: the two peaks may come from different cells; sampling=neighbourhood, flag nodata_neighbourhood). At 20 m or finer, NoData still scores dry (sampling=centre_nodata_dry) and is flagged for review (nodata_dry_review). A finite 0 is always dry. Recorded per receptor on Sampling / Notes (no new golden-schema CSV columns). Shared damsuite.nodata_sample; used by Hazard structures and roads/rail, the Screening/Runner nd_hazard sampler, Runner Receptors, and Hazard Lite. Named threshold, documented. Synthetic tests at 10, 20 and 30 m. Sibling: damit PR #67. damsuite.nodata_sample added; FILES.json refreshed.)
    1.1.0 (2026-11-12; unit system for the windows, display only): The plugins' own windows: unit_widgets.watch_window(window) converts every spin box whose suffix is a US unit and every spin box / line edit marked with the Qt property storedUnit (with its form label) when the window is shown; value()/setValue()/text()/setText() on those widgets keep the stored unit for the window's code. The settings grid shows SI values, units and starting values and stores what is typed back in the file's units. Reports: display_units.convert_text / convert_table / convert_row / convert_markdown write a human-readable report in SI ('<number> <unit>' quantities and chains like '0.1 / 1 / 2 ft', table columns whose header names a unit, key / value rows like 'Dam height (ft) | 27.5'); suite_styles.relabel_legend gives the depth / velocity raster legends SI labels on the same US class breaks. damsuite.display_units (pure Python) and ui.unit_widgets. One suite setting, unit_system = us (default) or si (QgsSettings ndsuite/unit_system, a project entry overrides it, env NDSUITE_UNITS for headless runs), set in DamSafety Setup > Suite setup / status. Under SI a Processing tool's number whose label declares ft, ft/s, mi, acres, ac-ft, cfs, in or sq mi is shown and typed in m, m/s, km, ha, m3, m3/s, mm or km2 in the standard tool dialog (UnitNumberWrapper, given by UnitParamsMixin.addParameter) and converted back before the tool runs; an untouched default reaches the tool exactly. The tool still receives its own unit: parameter keys, files, dam.json, the settings workbook, logs, qgis_process, batch and model designer dialogs (QGIS's own widget, stored unit) are unchanged; no datum changes. A label whose first parenthesis is not a unit (e.g. 'failure time (hr) or pool elevation (ft)') is never converted. UnitSpinBox for the plugins' own windows. Under US nothing changes. damsuite/FILES.json refreshed.
