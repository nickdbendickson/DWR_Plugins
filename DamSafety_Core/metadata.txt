about=Holds the one copy of the code the DamSafety plugins share: damsuite (dam records, the REG_05.2026 Fig. 5.1 / 5.2 curve table, the suite settings file, the offline data pack reader and builder, the pre-solve gate, version checks between the plugins) and the suite's window files and layer styles. Each DamSafety plugin's damsuite/ is a two-line shim onto this plugin, so a fix made here reaches every plugin at once and no two plugins can disagree. Every other DamSafety plugin lists this one in plugin_dependencies: QGIS offers to install it when one of them is installed.

changelog=1.1.0 (2026-11-12; unit system for the windows, display only): damsuite.display_units (pure Python) and ui.unit_widgets. One suite setting, unit_system = us (default) or si (QgsSettings ndsuite/unit_system, a project entry overrides it, env NDSUITE_UNITS for headless runs), set in DamSafety Setup > Suite setup / status. Under SI a Processing tool's number whose label declares ft, ft/s, mi, acres, ac-ft, cfs, in or sq mi is shown and typed in m, m/s, km, ha, m3, m3/s, mm or km2 in the standard tool dialog (UnitNumberWrapper, given by UnitParamsMixin.addParameter) and converted back before the tool runs; an untouched default reaches the tool exactly. The tool still receives its own unit: parameter keys, files, dam.json, the settings workbook, logs, qgis_process, batch and model designer dialogs (QGIS's own widget, stored unit) are unchanged; no datum changes. A label whose first parenthesis is not a unit (e.g. 'failure time (hr) or pool elevation (ft)') is never converted. UnitSpinBox for the plugins' own windows. Under US nothing changes. damsuite/FILES.json refreshed.
    1.0.2 (2026-11-09; audit M25 (stability): damsuite.dam_record.DamRecord.save stages to a per-writer hidden name (.dam.json.<pid>_<tid>.tmp - process id AND thread id) before os.replace, instead of a single shared dam.json.tmp. Two writers of the same dam.json - two suite processes, or a background classify thread racing the main thread - no longer byte-mix each other's record into invalid JSON that every later load rejects. Last-writer-wins across load / modify / save is unchanged and intended (no lock added); no computed value changes. damsuite/FILES.json refreshed.)
    1.0.1 (2026-11-09; audit M05: damsuite.tm11_curves.zone treats a cell beyond the velocity axis as high danger only if it holds water - a (depth > 0) guard on the v > vmax branch, so a dry cell with a huge velocity reads LOW, not HIGH (the depth-axis branch is never dry and is unchanged). damsuite/FILES.json refreshed. Used by DamSafety Hazard 2.24.1.)
    1.0.0 (2026-11-08; consolidation: one shared damsuite) First release. damsuite 1.18.9 (was vendored byte-identically into DamSafety Hazard, Runner, Screening and Data, with three modules in Setup, by tools/sync_damsuite.py against a pin) and the shared window files (was tools/sync_ui.py copies) move here, with the suite's QML layer styles (ui/styles/). alias.py makes `<Plugin>.damsuite` the same module objects as `DamSafety_Core.damsuite`, so the plugins' relative imports keep working with no second copy. damsuite.selfcheck() compares this plugin's damsuite files with its FILES.json; each plugin calls it at start-up as before. Tests: tests/test_alias.py (both import forms, identity, reload, the ImportError when this plugin is missing), tests/test_ui_shim.py.
