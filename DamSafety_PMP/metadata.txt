changelog=0.5.0 - DamSafety Core 1.0.0 - one shared damsuite (consolidation, 2026-11-08): this plugin no longer ships its own copy of the shared code. damsuite/ is a two-line shim onto the DamSafety Core plugin's damsuite package (DamSafety_Core/alias.py makes them the same module objects), and the shared window files (tokens, ui_widgets, ui_fit) are three-line shims onto DamSafety_Core/ui. Install DamSafety Core first: metadata plugin_dependencies names it, so the QGIS Plugin Manager offers it when this plugin is installed. No tool, default or number changes.
    0.4.5 - audit R3 (2026-11-07): core/pmp.py, core/gridutil.py and core/pothole.py called gdal.UseExceptions() / ogr.UseExceptions() at import. The call is process-wide in the GDAL bindings QGIS ships, so loading this plugin switched GDAL into exception mode for QGIS and every other plugin (code written for the default mode checks for None and met an exception instead). Removed; new core/gdalsafe.py (a local copy of the suite helper: checked / open_raster / open_vector / layer raise RuntimeError with GDAL's message in both modes, gdal_exceptions() turns exceptions on for one block and restores the setting) is used at every Open / Create / Warp / Polygonize in pmp, gridutil, pothole, spatial and temporal. Same behaviour in both GDAL modes; no result changes.
    0.4.4 - 2026-11-07 (usability / docs / release): metadata.txt names the real repository / tracker / homepage (https://github.com/nickdbendickson/dAmIt_Plugins; tools/ci_checks.py now rejects an example.com address, an empty repository= and author=Your Name), and the changelog= keeps its newest entries only: the older ones moved verbatim to docs/CHANGELOG.md ('Archived metadata changelog'), where the CI rule 'no changelog entry of the base is missing' finds them (changelog= over 12 KB now fails; QGIS's Plugin Manager renders the whole value of every installed plugin). A GitHub Release workflow (.github/workflows/release.yml, tag v*) builds the plugin zips and publishes plugins.xml to gh-pages, the QGIS plugin repository https://nickdbendickson.github.io/dAmIt_Plugins/plugins.xml. Root README.md written.
    0.4.1 - Plugin name (metadata) is "DamSafety PMP (prototype)", as the window title (was "ND PMP Tool (prototype)"; audit 2026-11-03, fix D).
    0.4.0 - New menu item Plugins > DamSafety PMP > Get basin data from StreamStats…: pick the outlet on the map (or a dam point), and USGS StreamStats (ss-delineate / ss-hydro, Jan 2026 services) outlines the basin, loads it as a layer and fills the drainage area, a suggested non-contributing area (ISOLAKESUM) and Tc / lag (Kirpich, or NRCS lag with your own CN; CN is never taken from StreamStats). A read-only panel shows the ND regression peaks 50%% - 0.2%% AEP (SIR 2015-5096) with ~90%% ranges and the Crippen & Bue envelope. Inflow hydrograph has an optional StreamStats basin file and then compares the PMF peak with the 0.2%% AEP peak and the envelope (warning only, never a failure). Requests go through QGIS networking (QGIS proxy settings apply) one at a time, 2 s apart, with a sha256 cache and a provenance file. Offline tests on saved responses.
    0.3.1 - QGIS 4 (Qt6): metadata declares supportsQt6=True and qgisMaximumVersion=4.99, like the other DamSafety plugins, so QGIS 4 no longer treats PMP as QGIS 3 only. No code change was needed: PMP has no Qt imports, and its QGIS enums (QgsProcessing.TypeVectorPolygon, QgsProcessingParameterNumber.Double, QgsProcessingParameterFile.Folder, QgsFeatureSink.FastInsert) resolve on QGIS 4.2.3 / PyQt6. Checked on QGIS 4.2.3: the 6 ndpmp algorithms register; pmp, inflow_hydrograph, spatial_distribution, snowmelt and export_hms run with the same results as QGIS 3.34 (pothole_storage was not run: no whitebox_tools). Metadata/compat only; no result changes.
