changelog=0.4.0 - New menu item Plugins > DamSafety PMP > Get basin data from StreamStats…: pick the outlet on the map (or a dam point), and USGS StreamStats (ss-delineate / ss-hydro, Jan 2026 services) outlines the basin, loads it as a layer and fills the drainage area, a suggested non-contributing area (ISOLAKESUM) and Tc / lag (Kirpich, or NRCS lag with your own CN; CN is never taken from StreamStats). A read-only panel shows the ND regression peaks 50%% - 0.2%% AEP (SIR 2015-5096) with ~90%% ranges and the Crippen & Bue envelope. Inflow hydrograph has an optional StreamStats basin file and then compares the PMF peak with the 0.2%% AEP peak and the envelope (warning only, never a failure). Requests are sent one at a time, 2 s apart, with a sha256 cache and a provenance file. Offline tests on saved responses.
    0.3.1 - QGIS 4 (Qt6): metadata declares supportsQt6=True and qgisMaximumVersion=4.99, like the other DamSafety plugins, so QGIS 4 no longer treats PMP as QGIS 3 only. No code change was needed: PMP has no Qt imports, and its QGIS enums (QgsProcessing.TypeVectorPolygon, QgsProcessingParameterNumber.Double, QgsProcessingParameterFile.Folder, QgsFeatureSink.FastInsert) resolve on QGIS 4.2.3 / PyQt6. Checked on QGIS 4.2.3: the 6 ndpmp algorithms register; pmp, inflow_hydrograph, spatial_distribution, snowmelt and export_hms run with the same results as QGIS 3.34 (pothole_storage was not run: no whitebox_tools). Metadata/compat only; no result changes.
    0.3.0 - Added to the DamSafety repo as DamSafety_PMP (nd_pmp 0.3.0, internal, experimental): no AWA data, no machine paths, light tests.
