description=Keeps North Dakota structure and building-footprint data on this computer and builds and refreshes the statewide offline data pack of the ND dam plugins (all layers, USGS 3DHP streams, SARP aquatic barriers).
about=Builds and keeps up to date the statewide offline data pack the ND Dam Hazard Helper, Breach Runner and Breach Screening read (one GeoPackage per layer: structures, roads, rail, lifelines, dams, USGS 3DHP flowlines and waterbodies, SARP aquatic barrier dams and surveyed crossings, DWR and HIFLD layers, NLCD land cover). Also downloads and maintains local North Dakota copies of the National Structure Inventory (NSI API; NSI 2026 and NSI 2022 merged into one layer by default), Microsoft building footprints, OpenStreetMap (Geofabrik), optionally FEMA/ORNL USA Structures, and optionally the USACE-NSI/nsi-generator source code. Each dataset is checked cheaply (checksum, ETag or latest commit) and only re-downloaded when it changed. Updates are staged and verified before replacing the local copy, so the data stays usable offline and an interrupted update never leaves partial files. Layers already in the project are reloaded after an update. A long run (a full pack build takes about 90 minutes) runs in the background, says which layer it is on, can be stopped at any time, and ends with a plain-words summary of what was not fetched and what that costs. The pack window shows the pack layer by layer with its vintage and feature count, fetches one layer again, takes your own file instead of a downloaded layer, copies the pack to a USB stick with a checksum file for a field laptop with no internet, imports one back, reports what a refresh changed and which already-classified dams that makes out of date, and checks whether the services answer before a run that would hang.

changelog=1.4.1 - Runs in QGIS 4 (Qt6): the plugin declares Qt6 support and every Qt and QGIS enum it uses is spelled for both Qt5 and Qt6 (qtcompat.py), as the three dam plugins already did. Before, QGIS 4 would not load it, and step 1 of the suite with it. With ND Dam Hazard 2.30.1, ND Dam Breach Runner 3.20.1 and ND Dam Breach Screening 0.28.1 (damsuite 1.16.1). Nothing else changes.
  1.4.0 - Usability: a run now says which layer it is on ("layer 12 of 29: USACE National Structure Inventory") in the status bar and in the plugin's windows, every window has a Stop button, and a run ends with a short block in plain words - how many layers were built and what was not fetched, with the consequence ("Not fetched (blocked or down): traffic counts, OSM parks and places. The plugins run without these; the Hazard report will say 'no traffic counts'."). A lock file left behind by a killed run no longer blocks every later run: the recorded process is checked and a dead one's lock is cleared and said so once. In 3DHP mode "auto" the web service is given a few minutes (settable) to answer a small question and the statewide question a build really asks; when it does not, the National Map file route is taken straight away with the reason in the log, instead of waiting out 25 minutes of HTTP 504. The data folder is now adopted by the three dam plugins in one step (suite data folder, pack location, data source and Dams folder together), so a folder chosen here is the folder they read. New "Rebuild only missing layers", which is what a refresh already did for missing layers.
  New in 1.4.0: an "Offline Pack and Data Folder..." window - one row per pack layer with its vintage and feature count, "Fetch again" for one layer and "Replace with my file..." for a layer you have a better file for (a layer holding your own file is then left alone by every refresh, however old it is, until you press "Fetch again" on it; the manifest records who put the file in and when, and the end-of-run summary says the layer was left alone); the suite readiness lights and one row per drop-in folder (dwr/, hifld/, dem/, nlcd/, terrain/) with what goes in it, where it comes from and "Open folder"; "Copy pack to USB..." and "Import pack...", which copy the pack with a CHECKSUMS.sha256 file and verify every file before replacing anything, so a field laptop with no internet can use the office machine's pack; a pack change report after every refresh (new structures, new addresses, new roads - and which already-classified dams are now out of date), which can be saved next to the pack; a data-vintage list (layer, source, download date, feature count) for stamping reports; and a service check (NSI, 3DHP small and statewide, NID, FEMA, DWR, MRLC) that reports reachable / slow / down on demand or when the window opens, to warn before a run that would hang. New tests/ folder: 64 tests that run without QGIS.
  1.3.0 - New source "Offline pack for the ND dam plugins": builds the whole statewide offline pack (33 layers) in <data folder>/ND_Dam_Suite_Pack and keeps it up to date (a missing or incomplete layer is built, a layer older than the refresh interval is fetched again, the rest is left alone). Includes the USGS 3DHP flowlines and waterbodies (replacing NHD) and the SARP aquatic barrier dams and surveyed road-stream crossings. When the 3DHP web service does not answer, the National Map's 3DHP national file is downloaded once (about 12 GB, resumes) and the area is cut out of it. The ND dam plugins can be pointed at the pack automatically. "Add North Dakota Layers to Project" also adds the 3DHP and SARP layers. The pack takes its five OpenStreetMap layers from the OpenStreetMap pack layers dataset (1.2.0) when it has built them, and asks Overpass only without them.
  1.2.0 - New dataset 'OpenStreetMap pack layers (Geofabrik)': downloads Geofabrik's full North Dakota extract (.osm.pbf) and builds the five OSM layers the ND dam suite reads (OSM_lifelines, OSM_crossings, OSM_campgrounds, OSM_trailer_parks, OSM_places) as GeoPackages in the osm_layers folder. Uses the GDAL of QGIS.
  1.1.0 - NSI now names its version (the API default switched to NSI 2026). By default NSI 2026 and NSI 2022 are merged into one layer: a 2022 point within 30 m of a 2026 point is folded into it (2026 wins; the 2022 id, occupancy, building type and a mobile-home flag are kept in nsi22_* fields), and 2022 points with no 2026 point nearby are kept with nsi_version = 2022. Settings choose merged / 2026 only / 2022 only and the match distance. nsi_summary.json in the nsi folder gives counts per county.
  1.0.1 - OpenStreetMap now downloads as a GeoPackage (north-dakota-latest-free.gpkg.zip); only its buildings layer is added to the project.
  1.0.0 - First release.
